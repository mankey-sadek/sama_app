# سَما — مشروع تطبيق المكالمات عبر الإنترنت الفضائي

المشروع ده مكوّن من جزئين:

```
sama_app/            تطبيق Flutter الحقيقي (أندرويد + iOS) — كل الشاشات + مكالمات WebRTC فعلية
signaling-server/     سيرفر Node.js بسيط لتبادل رسائل بدء المكالمة بين طرفين
```

## ملاحظة مهمة عن بيئة التطوير دي

البيئة اللي بشتغل فيها (Cowork Cloud) ممنوعة من الوصول لـ `storage.googleapis.com`،
وهو المصدر اللي أداة `flutter` بتنزّل منه Dart SDK ومحرّك Flutter نفسه أول مرة.
معنى كده إني قدرت أكتب كل كود Flutter كامل ومتماسك، لكن **مقدرتش أشغّل
`flutter pub get` أو `flutter run` هنا فعليًا لأتأكد إنه بيتصرّف بالظبط زي
المتوقع على جهاز حقيقي**.

اللي قدرت أعمله فعلاً وأتأكد إنه شغال 100%: **سيرفر الإشارات (Signaling
Server)**. ده جزء Node.js عادي مش محتاج Flutter، وشغّلت اختباره فعليًا
في هذه الجلسة ونجح (شوف `signaling-server/test/test_signaling.js`) —
يعني منطق تبادل رسائل بدء المكالمة (offer/answer/ice-candidate/hangup)
اتأكد إنه شغال صح.

## إزاي تجرّب المشروع على جهازك

### 1) شغّل سيرفر الإشارات
```bash
cd signaling-server
npm install
npm start          # هيشتغل على المنفذ 4000
# للتأكد إن كل حاجة تمام:
npm test
```

### 2) شغّل تطبيق Flutter
لازم يكون عندك Flutter SDK مثبت على جهازك (`flutter doctor` يطلع كله ✓).
```bash
cd sama_app
flutter pub get
flutter run
```

بما إن التطبيق بيتصل بسيرفر الإشارات على `ws://10.0.2.2:4000` افتراضيًا
(عنوان محاكي أندرويد اللي بيشاور على localhost بتاع جهازك)، لو بتجرّب
على:
- **محاكي أندرويد**: العنوان الافتراضي هيشتغل زي ما هو.
- **جهاز iOS / حقيقي**: غيّر العنوان لـ IP جهازك على نفس الشبكة، مثلاً:
  ```bash
  flutter run --dart-define=SIGNALING_SERVER_URL=ws://192.168.1.5:4000
  ```

### 3) تجربة مكالمة حقيقية بين جهازين
1. شغّل التطبيق على جهازين (أو محاكي + جهاز حقيقي) على نفس الشبكة.
2. سجّل دخول برقمين مختلفين في كل نسخة (رقم الهاتف هو المعرّف المؤقت).
3. من الشاشة الرئيسية، اضغط على أي جهة اتصال — هيبعت offer حقيقي عن
   طريق WebRTC. حاليًا الاتصال ثابت بمعرّف `ahmed` / `shipping-co` ...إلخ
   من `lib/models/contact.dart`، فلو عايز تكلّم الجهاز التاني فعلاً،
   غيّر `id` بتاع أول Contact في الليست ليكون نفس رقم الهاتف اللي
   سجّلت بيه دخولك على الجهاز التاني (تفصيل تجريبي هيتظبط لما نضيف
   دفتر جهات اتصال حقيقي من الـ Backend).

## اللي شغال فعلي دلوقتي (مش مجرد واجهة)

- فتح المايك والحصول على صوت المستخدم (`getUserMedia`)
- إنشاء اتصال WebRTC حقيقي (Peer Connection) وتبادل offer/answer
- تبادل ICE candidates عن طريق سيرفر الإشارات
- كتم/إلغاء كتم المايك فعليًا أثناء المكالمة
- قياس دوري لجودة الاتصال من إحصاءات WebRTC (فقد حزم + RTT) وعرضها
  في الواجهة

## اللي لسه ناقص قبل أي إطلاق حقيقي

- **TURN server** حقيقي (زي coturn) — الـ STUN العام من جوجل مش هيكفي
  خلف شبكات NAT معقدة، وده متوقع جدًا مع أجهزة استقبال الإنترنت الفضائي.
- **مصادقة حقيقية** (OTP فعلي / Auth0 / Firebase) بدل الاكتفاء برقم الهاتف.
- **دفتر جهات اتصال حقيقي** من Backend API بدل البيانات الوهمية في
  `contact.dart`.
- **إشعارات المكالمة الواردة** وقت التطبيق مقفول (FCM / APNs) — دلوقتي
  الاستقبال بيشتغل بس والتطبيق فاتح وعلى الشاشة الرئيسية.
- **دعم المكالمات الجماعية** عن طريق SFU (mediasoup) لحسابات الشركات.
- طبقة حسابات المؤسسات (Multi-Tenancy) ولوحة تحكم الشركات، زي ما اتفقنا
  في وثيقة المعمارية.

## هيكل كود Flutter

```
lib/
  main.dart                     نقطة الدخول + إعداد الاتجاه RTL
  theme/app_theme.dart          نفس ألوان النموذج الأولي بالظبط
  models/contact.dart           موديل جهة الاتصال + بيانات وهمية للعرض
  services/signaling_service.dart   عميل WebSocket لسيرفر الإشارات
  services/webrtc_service.dart      منطق WebRTC الحقيقي (offer/answer/ICE/جودة)
  screens/splash_screen.dart
  screens/account_type_screen.dart  اختيار فردي / شركة
  screens/login_screen.dart
  screens/home_screen.dart          قائمة المكالمات + بدء مكالمة
  screens/call_screen.dart          شاشة المكالمة الحقيقية
  screens/settings_screen.dart
  widgets/satellite_signal_indicator.dart
```
